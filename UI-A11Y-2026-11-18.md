### F2: GPU telemetry, how it works

- Source: Windows performance counters `GPU Engine(*)\Utilization Percentage` and
  `GPU Adapter Memory(*)\Dedicated Usage`. Task Manager uses the same counters, so the numbers match it.
  This works for the RX 9070 XT. `nvidia-smi` and `rocm-smi` are not used here.
- GPU % = add every process on one engine, then take the busiest engine (Task Manager's method).
- Cost: one PDH query is opened once and re-read. One read took **4 ms** on this PC. It runs on a worker
  thread (`spawn_blocking`), never on the UI thread. It runs every 3 s, only while Operations is open and the
  window is visible. The value is the average since the last read, so no load spike is missed.
- On this PC (`cargo test live_gpu -- --ignored --nocapture`): RX 9070 XT 96% load, 15.0 / 15.8 GB VRAM
  (another session had a model loaded), Radeon iGPU 0%.
- UI: one card per GPU in the CPU / RAM row (load %, name, VRAM used / total, bar), plus a GPU trend next to
  the CPU and RAM trends. If the counters are missing, the card says why. CPU and RAM still update.
- The Node page GPU card now shows live VRAM and load too, in place of "VRAM telemetry unavailable".

## How to check each fix

1. Chat, F1: make a queue (send 2 messages while a reply streams), then drag-select the whole chat.
   Only message text is highlighted, never the button labels.
2. Chat, F8: Tab to a bot card, press Alt+Down, then Alt+Up. The bot moves and keeps focus.
3. Operations, F2: open OPERATIONS. Right of CPU LOAD and RAM AVAILABLE: "GPU 1 LOAD" with the RX 9070 XT,
   VRAM used / total. Load a model in llama-swap and watch the % and VRAM rise within 3 s.
4. Operations, F4: minimise the app. Task Manager shows Atlas CPU use near 0.
5. Node: move the CPU ceiling slider. The "Unsaved changes" note shows. Click Save policy. The note goes.
